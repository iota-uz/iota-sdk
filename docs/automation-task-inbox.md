# Входящие задачи автоматизаций («Мои задачи»)

Раздел `/automations/tasks` модуля `modules/automations` показывает человеку задачи human-нод
автоматизаций, назначенные ему лично, его ролям, группам или permission, а также переданные ему
делегированием. Отдельной таблицы нет: задача — это `workflow.Task` human tasks substrate
(`pkg/extruntime/workflow`), а инструкции, кнопки и форма берутся из запуска, который открыл задачу,
и из версии графа, к которой этот запуск закреплён.

## Страницы

- `/automations/tasks?tab=mine|overdue|decided&q=…` — вкладки «Мои», «Просроченные», «Решённые мной»,
  поиск по названию задачи и метке записи. Вкладка и поиск хранятся в URL.
- `/automations/tasks/{id}` — задача: инструкции (markdown без HTML), поля по JSON Schema ноды,
  комментарий, кнопка на каждый outcome. Danger-outcome подтверждается в панели над кнопками.
  После решения открывается следующая задача вкладки и показывается тост.
- Пункт навигации «Мои задачи» видят все пользователи; счётчик открытых задач обновляется по
  событию HTMX `automations:tasks-changed` и раз в две минуты (`application.NavNode.Badge`).
- Чужая, закрытая для пользователя или удалённая задача открывает экран «Задача недоступна», а не 404-страницу.

Решение и делегирование принимаются только из интерактивной сессии человека. Запрос с заголовком
`Authorization` или из агентской сессии получает `HUMAN_REQUIRED` (403).

## Сервис

`tasks.TaskInbox` (`modules/automations/tasks`): `List`, `Get`, `Counts`, `Decide`, `Delegate`.
Видимость считается по **текущему** членству (`workflow.TaskAudience`): вышедший из роли или группы
задачу не видит и получает `ErrTaskNotFound`. Повторная отправка того же решения идемпотентна,
другой outcome после своего решения — `ErrAlreadyDecided`, решение закрытой задачи — `ErrTaskClosed`.

Происхождение действия передаётся в контексте: `tasks.WithOrigin(ctx, engine.OriginHuman)`.

## Своя форма решения: `TaskForm`

Модуль или коннектор регистрирует форму:

```go
tasks.ContributeTaskForm(builder, myForm) // Kind() уникален; дубль останавливает запуск приложения
```

Human-нода выбирает её аннотацией в своей форме:

```json
{"form": {"type": "object", "x-iota-form": "eimzo.sign", "properties": {}}}
```

- Аннотация без зарегистрированной формы — ошибка валидации графа при сохранении.
- Вид формы читается из параметров ноды в закреплённой версии графа запуска. Если формы в
  приложении больше нет, открытая задача показывает «Форма недоступна», и решение заблокировано.
- `Render` рисуется внутри `<form>`, который отправляет `POST /automations/tasks/{id}/decide`.
  Данные своей формы передаются полем `form` (JSON), необязательный комментарий — полем `comment`.
- `Decide` выполняется до записи решения и вне транзакции. Ошибка оставляет задачу открытой;
  `*tasks.FormError{Message}` показывается человеку как есть, другие ошибки — общей фразой.
  Внешний эффект внутри `Decide` должен быть безопасен к повтору.

## Уведомление исполнителям

Модуль регистрирует native-событие `automation.task.assigned.v1` (`automations.Natives`), наблюдатель
движка, который его публикует, и определение уведомления `tasks.NotificationDefinition`:

- получатели по умолчанию — `assignees` (`user_ids` события);
- ссылка — `/automations/tasks/{task_id}`;
- текст зависит от причины: назначение, делегирование («<кто> передал вам задачу»), эскалация;
- при доставке получатель проверяется: читать задачу может её текущая аудитория (включая делегата)
  и держатель `Automations.Read`. Правило подключено к ядру уведомлений как правило сущности
  `automation.task` (`notifications.ContributeSubjectAccess`): общий `NotificationSubjectAccess`
  приложения о задачах не спрашивается.

## Подпись записи

Метка и ссылка записи (subject) берутся у модуля, владеющего сущностью:
`subjects.Contribute(builder, entity, factory)` (`pkg/automation/subjects`, готовый `TableNamer`).
Ядро называет `core.user`, CRM — `crm.client`: по имени записи, со ссылкой на карточку только для
пользователя с правом чтения (`User.Read`, `Client.Read`). Сущность без namer называется своим
названием, без ссылки. Свою политику целиком задаёт `automations.WithSubjectNames`.

## Сроки

«Просроченные» — открытые задачи с `DueAt < now`, у которых ещё есть шаг эскалации. Открытая задача,
у которой прошёл финальный срок, показывается истёкшей и решения не принимает
(`workflow.Task.PastFinalDeadline`, тот же предикат, что у substrate): своя форма в таком случае не
вызывается.

## Ошибки HTTP

Запрос решения или делегирования не из интерактивной сессии человека получает 403 с телом
`{"error":{"code":"HUMAN_REQUIRED","message":"…"}}` и заголовком `X-Error-Code: HUMAN_REQUIRED` —
до чтения задачи.
