# Стандарт UI/UX автоматизаций

Документ применяется к каждому экрану автоматизаций: редактор графа, «Интеграции», страницы автоматизаций, вид запусков, входящие задачи, каналы уведомлений, формы подписи, настройки уведомлений. Критерии сформулированы как «условие → что видно». Номера критериев стабильны, задачи ссылаются на них.

Каждая UI-задача автоматизаций ссылается на этот документ как на обязательную приёмку. В своём разделе «UI и UX» задача пишет только чек-лист своего экрана и отклонения от стандарта, принятые в задаче.

## Как проверять

Тег в конце строки называет способ проверки:

- `[VR]` — скриншот-тест;
- `[e2e]` — Playwright-сценарий;
- `[axe]` — проверка `expectNoA11yViolations` из `@iota-uz/sdk/testing`;
- `[unit]` — тест компонента или функции;
- `[ручн.]` — проверка QA вручную со скриншотами или видео в PR.

Рабочие ширины: 1440, 1200 и 390 px, светлая и тёмная тема.

Стек экранов:

- Solid-экраны используют компоненты и токены `@iota-uz/sdk/solid-ui`.
- templ/HTMX-экраны используют templ-компоненты SDK с теми же токенами.
- Свой цвет, отступ или тень вне токенов не допускается.

Компоненты SDK, на которых стоят критерии:

| Критерий | Solid (`@iota-uz/sdk/solid-ui`) | templ |
| --- | --- | --- |
| F4 | `Dialog`, `Drawer`, `ViewDrawer`, `ConfirmationDialog` с `busy` и `busyMessage`; `DialogBusyStatus` над кнопками своей модалки | — |
| F6, U1 | `Toast`/`ToastProvider` с `action: { label, onAction }` | `components/base/toast` и `htmx.TriggerToastWithAction(w, variant, title, message, htmx.ToastAction{Label, HxPost \| Href})` |
| A1 | `expectNoA11yViolations(page, { include, exclude, disableRules })` из `@iota-uz/sdk/testing` (нужен dev-пакет `@axe-core/playwright`) | то же |

Экран с фиксированной нижней панелью действий задаёт её высоту в CSS-переменной `--iota-toast-offset-bottom`; на ширине ≤ 480 px тосты стоят над панелью.

## 1. Состояния экрана

- **S1** Каждый экран и каждая панель отрисованы во всех применимых состояниях: загрузка, пусто, пусто под фильтром, ошибка, частичные данные, нет прав, устаревшие данные, только чтение. Каждое состояние есть в VR-галерее экрана. [VR]
- **S2** Загрузка → скелетон формы будущего контента с теми же размерами. Пустой экран или одиночный спиннер на всю страницу не допускаются. После загрузки контент не сдвигается: CLS ≤ 0.02. [VR] [e2e]
- **S3** Пусто → фраза, что здесь появится и откуда, и одно основное действие. Пусто под фильтром → «Ничего не найдено по …» и «Сбросить фильтры» — единственная кнопка сброса на экране. [VR]
- **S4** Ошибка чтения → человеческая фраза, причина (если известна) и «Повторить», которое повторяет тот же запрос. Если данные уже читались, они остаются с пометкой «Не удалось обновить · данные на <время>». [e2e]
- **S5** Нет прав (403) → «Нужны права <право словами>» без кнопок действий. Действия без прав не рендерятся: их нет в DOM, в Tab-порядке и для скринридера, а не `display:none`. [e2e]
- **S6** Ответ на более старый запрос никогда не заменяет более новый: быстрая смена фильтра A → B показывает B. Относительные времена обновляются одним таймером раз в минуту. [unit]
- **S7** Нет сети или сервер недоступен → баннер «Нет соединения · Повторить». После возврата сети данные перечитываются сами, правки черновика не теряются. [e2e: `context.setOffline`]
- **S8** Только чтение (старая версия, нет права, телефон, граф сохранён агентом) → баннер называет причину и действие («Открыть текущую версию»). [VR]

## 2. Обратная связь на действие

- **F1** Любое действие проходит одни и те же состояния: готово → идёт → долго → ошибка | готово. С кадра нажатия кнопка показывает спиннер и глагол в процессе («Сохраняем…»). Повторный клик во время запроса игнорируется: в сети ровно один запрос. [e2e: задержка ответа 6 с]
- **F2** Через 4 с без ответа → строка «Всё ещё ждём <чего>», и в ней сказано, что ничего не запустится дважды. [e2e]
- **F3** Ошибка → фраза рядом с действием (`role="alert"`), кнопка становится «Повторить». Повтор отправляет запрос с тем же ключом идемпотентности; новый ключ на каждый клик запрещён. [e2e: проверка запроса]
- **F4** Пока идёт запрос, модалку и шторку нельзя закрыть ни ✕, ни Esc, ни кликом по фону, ни Cancel. Содержимое приглушено (`aria-busy`). Попытка закрыть показывает строку статуса. Реализуется prop `busy`. [e2e]
- **F5** Успех → короткий тост с итогом. Модалка закрывается, изменённая строка или карточка коротко подсвечивается (около 4 с). Если человек ушёл со страницы посреди запроса, итог всё равно приходит тостом из корня приложения. [e2e]
- **F6** Тосты: светлая поверхность; у ошибки есть «Повторить»; у обратимого действия есть «Отменить»; учитывают `safe-area-inset`; на 390 px почти во всю ширину; не перекрывают основную кнопку. Реализуется слотом `action` в solid-ui и templ. [VR]
- **F7** Цветных плашек-заливок для статуса нет. Статус — строка с точкой или иконкой над кнопками, под тонкой линией. [VR]
- **F8** Optimistic UI допустим только для обратимых и дешёвых правок (переключатель, переименование, раскладка). Отказ сервера откатывает значение и показывает причину. Необратимое и платное ждёт ответа сервера: строка исчезает из списка только после успеха. [e2e]
- **F9** Работа дольше минуты не держит модалку: она уходит в фоновую задачу со статусом и ссылкой на результат. [ручн.]

## 3. Клавиатура и фокус

- **K1** Каждое действие доступно с клавиатуры. Таблица «клавиша → результат» прикладывается к PR. [e2e]
- **K2** Фокус всегда виден (`:focus-visible`, токен `border-brand`), в том числе у деструктивных кнопок. Порядок Tab совпадает с визуальным. [VR фокус-состояний] [e2e]
- **K3** У модалок, шторок и палитр есть ловушка фокуса. Esc закрывает верхний слой, затем следующий. Фокус возвращается на элемент, который открыл слой. [e2e]
- **K4** Меню, поповеры и палитры закрываются любым нажатием вне них (`pointerdown` в фазе capture), при скролле или зуме, `blur` окна и изменении ширины окна. Нажатие, которое закрыло меню, не срабатывает на элементе под ним. [e2e]
- **K5** Списки и комбобоксы: ↑ ↓ двигают выбор, Enter выбирает, Esc закрывает без изменений. Поиск со счётчиком «7 из 15» и подсветкой совпадения. Пустой результат → «Ничего не подходит под «…»». Нативный `<select>` не используется, если вариантов больше пяти: вместо него `Combobox`/`SearchSelect`. [e2e]
- **K6** Горячие клавиши не срабатывают, пока фокус в поле ввода. ⌘Z в поле отменяет ввод, а не правку документа. Модификатор зависит от ОС: ⌘ на macOS, Ctrl на Windows и Linux. [unit]
- **K7** Поле сообщения или комментария: Enter отправляет, Shift+Enter переносит строку; во время IME Enter ничего не отправляет; на touch Enter переносит строку; пустое поле не отправляется; под полем подсказка. Длинные поля отправляются ⌘/Ctrl+Enter. [unit]

## 4. Доступность

- **A1** `expectNoA11yViolations` на каждом экране и в каждом состоянии из S1, при 1440 и 390 px, в обеих темах: 0 нарушений serious и critical. [axe]
- **A2** Контраст: обычный и приглушённый текст ≥ 4.5:1; крупный текст, значимые иконки, рамки контролов и тона исходов ≥ 3:1, в обеих темах. [axe] [unit на токены]
- **A3** У каждого интерактивного элемента есть роль и доступное имя. Кнопка-иконка получает `aria-label` из локали. Группы и ноды получают `role="group"` с `aria-label`. [axe]
- **A4** Асинхронный статус — `role="status"`, ошибка — `role="alert"`, живой счётчик — `aria-live="polite"` только на изменяющемся фрагменте. [unit]
- **A5** Статус никогда не передаётся только цветом: у каждого цветного состояния есть иконка или текст. [VR в grayscale] [ручн.]
- **A6** `prefers-reduced-motion: reduce` → анимаций нет, задержки ухода слоя нет, анимированные рёбра и пульсации статичны. [VR с эмуляцией]
- **A7** Анимации открытия и закрытия слоёв и раскрытия панели длятся 120–200 мс. Слой уходит обратной анимацией (около 140 мс). Уходящий слой `inert` и не держит фокус. [ручн.]

## 5. Touch, телефон, узкие окна

- **T1** Цели касания ≥ 44 px на `pointer: coarse`, ≥ 36 px для курсора: строки меню, вкладки, контролы холста, чипы, кнопка «назад». [e2e: обход bounding box видимых контролов]
- **T2** `:hover`-стили только под `(hover: hover)`. Нажатие отвечает через `:active`. Ни одно действие не доступно только наведением: подсказки и причины disabled на touch показываются по тапу. `title` не единственный носитель смысла. [e2e на iPad-эмуляции]
- **T3** Подсказки называют жест на touch и клавиши на десктопе. Сочетания клавиш в меню на touch не показываются. [VR coarse]
- **T4** Экранная клавиатура не закрывает активное поле и основные кнопки. Слои ограничены `visualViewport`, а не `innerHeight`. Слой закрывается при смене ширины окна, а не высоты. [ручн. iOS Safari] [unit расчёта]
- **T5** Прокручиваемые списки в слоях прокручиваются пальцем внутри себя (`overscroll-behavior: contain`), фон под скримом не двигается. [e2e touch]
- **T6** На 390 px нет горизонтального скролла страницы. Таблицы превращаются в карточки или прокручиваются внутри контейнера. Шапка в одну строку: путь обрезается многоточием, кнопки не сжимаются. [VR 390] [e2e `scrollWidth ≤ clientWidth`]
- **T7** Политику телефона задаёт экран явно, в своей задаче:
  - редактор графа на телефоне только для просмотра, элементы правки не рендерятся;
  - экраны-решения полностью работают на 390 px одной рукой;
  - экран, который не работает на телефоне, показывает «Откройте на компьютере» и «Скопировать ссылку», а не сломанный виджет.
  - [VR 390]
- **T8** Узкое окно десктопа (1200 px) и планшет используют десктопную раскладку и редактируют как десктоп. [VR 1200]

## 6. Тексты и микрокопирайт

- **C1** Человек никогда не видит сырой id (uuid, `run_…`), код ошибки (`VALIDATION_FAILED`, HTTP 502), `e.message`, HTML-ответ провайдера, стек, JSON-текст вместо поля формы. Технический id — только внизу деталей строкой «ID · Скопировать». Код ошибки уходит в `console.warn` и в лог. [e2e: поиск по DOM `/[0-9a-f-]{36}|[A-Z_]{6,}/`] [unit маппинга ошибок]
- **C2** Каждая серверная ошибка, которую может получить экран, имеет локализованную фразу: что случилось и что делать. Неизвестный код → «Не удалось <действие>. Повторите через минуту.». Сырой ответ провайдера — только под раскрывашкой «Показать ответ сервиса». [unit]
- **C3** Сущности называются по смыслу: триггер — «Каждый день в 20:00», «При подписании документа»; connection и пользователь — по имени; статус — словами. Имена собирает одна функция, общая для списка, холста и деталей. [unit]
- **C4** Локали en, ru, uz, uz-Cyrl: все строки, aria-label, тосты и ошибки есть во всех четырёх; `just check tr` зелёный; плюрализация по правилам языка; даты, время и числа по локали и часовому поясу тенанта; VR одного экрана снят на ru, и ничего не обрезано без многоточия и `title`. [VR ru] [CI]
- **C5** Тон: коротко, глагол в кнопке, а не «ОК» или «Да»; кнопка подтверждения повторяет действие; без восклицаний и вины пользователя; одно понятие везде называется одним словом. [ручн.]

## 7. Визуальная система

- **V1** Только токены SDK: цвета, `border-subtle`/`default`/`strong`/`brand`/`danger`, отступы по шкале Tailwind SDK, радиусы и тени из `styles/tailwind/iota.css`. `border-gray-*` и hex в компонентах экрана запрещены. [lint/grep в CI]
- **V2** Компоненты solid-ui используются как есть. Новое состояние компонента добавляется в solid-ui (`src/catalog.ts`) со скриншотом в обеих темах, а не пишется локально в экране. [VR solid-ui]
- **V3** Иконки одного набора и размера в одном ряду, по базовой линии текста. Числа и таймеры — `tabular-nums`. [VR]
- **V4** Каждый экран и состояние снимается в светлой и тёмной теме. В тёмной теме нет белых вспышек при загрузке и светлых островов сторонних виджетов. [VR]

## 8. Воспринимаемая производительность

- **P1** Отклик на ввод ≤ 100 мс. Первый осмысленный кадр (скелетон) ≤ 300 мс после навигации. Данные списка ≤ 1 с на p95 локального стека. [e2e с метриками]
- **P2** Нет сдвига раскладки, когда появляются строка фильтров, баннер, счётчики, статус под кнопками: место зарезервировано. [VR до и после]
- **P3** Тяжёлые чанки грузятся lazy только на своём экране, базовый host их не тянет: это проверяет release check. [CI]
- **P4** Живые данные обновляют только изменившиеся элементы, на ответе опроса ничего не мигает. Индикатор соединения: «В эфире», «Переподключение…», «Завершено». [VR] [e2e]

## 9. Подтверждения, необратимое, Undo

- **U1** Обратимое действие выполняется сразу, с «Отменить» в тосте. Необратимое идёт через подтверждение: кнопка с глаголом и тоном danger, фокус по умолчанию на «Отмена», сказано, что будет потеряно. Что обратимо, решает задача экрана. [e2e]
- **U2** Отказ сервера в подтверждении объясняется внутри открытого диалога, диалог не закрывается. [e2e]
- **U3** Подтверждение хода, где возможно, встроено в панель над кнопками, а не открывается модалкой поверх. Панель сразу рисуется из уже известных данных. [ручн.]
- **U4** В редакторах Undo/Redo (⌘Z, ⇧⌘Z и кнопки): одно действие пользователя — один шаг; одно перетаскивание — один шаг; Save историю не очищает. [unit] [e2e]

## 10. Автосохранение и конфликты

- **AS1** То, что не меняет поведения (раскладка, ширина колонок, свёрнутые панели), сохраняется само через 500 мс после конца действия. Тихий статус «Сохраняем…» → «Сохранено», при ошибке «Не сохранено · Повторить». Версия не создаётся. [e2e]
- **AS2** То, что меняет поведение, сохраняется явно. При уходе со страницы с несохранёнными правками — предупреждение. [e2e]
- **AS3** Конфликт версии → «Изменено <кем> в <время>». Правки остаются на экране, человек выбирает «Загрузить их версию» или «Сохранить мою поверх vN». [e2e]

## 11. URL и deep links

- **D1** Вкладка, фильтры, поиск, выбранная строка, открытая шторка и выбранная нода хранятся в URL. Перезагрузка и открытие ссылки в новой вкладке восстанавливают тот же вид. Назад закрывает шторку, а не уводит со страницы. [e2e]
- **D2** «Сбросить фильтры» снимает только параметры фильтров. Возврат к списку восстанавливает последние фильтры. [e2e]
- **D3** Ссылка, которая знает только id объекта, открывает его в родном контексте. Нет прав или объект удалён — понятный экран, а не 500. [e2e]

## 12. Тесты и артефакты в PR

- **Q1** VR для каждого экрана и состояния из S1: 1440 и 390 px (1200, если у экрана есть брейкпоинт), light и dark, Linux-baseline канонический, допуск 0 px. Компоненты — в `web/solid-ui/vr`, экраны пакета — по образцу VR-историй `web/lens/vr`, templ-экраны — через Playwright `toHaveScreenshot`. [VR]
- **Q2** Playwright e2e для каждого ключевого сценария экрана на локальном стеке, включая ошибку, «долго» и «нет прав». [e2e]
- **Q3** В PR: скриншоты «до и после» каждого экрана (1440 и 390, light и dark), таблица клавиш (K1), результат axe (A1), для холста — профиль производительности.
- **Q4** Для touch-экранов: Playwright WebKit iPad (портрет и альбом) и Chromium с настоящими touch-событиями (CDP `Input.dispatchTouchEvent`). Что не проверено на реальном устройстве, перечислено в PR. [e2e] [ручн.]

## 13. Уроки, которые стандарт закрепляет

Эти ошибки встречались в похожих редакторах графов и досках задач. Каждая закрыта критерием выше.

- Приёмка на пустом графе пропускает дефекты прод-данных: когда все исходы уже соединены, тянуть стало нечего. Сценарии холста проверяются на графе, где все исходы соединены.
- Фон холста взял фактурный токен других страниц и стал невидим. У холста свой токен, проверенный скриншотом в обеих темах (V4).
- Технические id вместо имён и поля, неприменимые к объекту (фильтр у расписания), запутывают. Имена по смыслу, поле только там, где применимо (C1, C3).
- Nullable-схема уходила в запасной JSON-редактор. Каждое поле — нормальный контрол, JSON-текст только для схемы без типа.
- Два способа сделать одно (стрелка и выпадающий список) дают расхождения. Один способ, плюс клавиатурный эквивалент.
- Перемещение узла создавало новую версию. Раскладка сохраняется отдельно от версии (AS1).
