# Reusable Lens reports

A Definition stores a permanent source reference, source contract version, view and parameters. It never stores SQL, an executed frame or a snapshot ID. A Placement references that definition and owns its caption, width and parameter overrides. A Composition stores ordered rows of placements.

The host resolves authorized definitions and sources. Catalog is the code-authored adapter; persistence implements the same Host interface. SourceFunc binds domain data to existing Lens DashboardSpec blocks. Compose namespaces each block's datasets, panels, variables and explorers and lowers it into the existing runtime. It does not add a request manager or executor. Grid groups preserve compound blocks, their titles and nested row geometry on the wire.

Parameters are applied in definition → composition → placement order. Unsupported parameters and views fail explicitly. Sources validate parameter values and bind them before building a spec. Calendar/timezone, dimension semantics, SQL and tenant/user scope remain host-owned. Composition.Context supplies immutable host calendar and dashboard/card/section/group layers. Definition.Filters owns saved report defaults. Periods override by scope; dimension constraints intersect with full provenance. Unsupported or conflicting contexts block source execution. ContextSource must translate the resolved context explicitly; no fallback executes a broader query. The wire group carries the same effective context and identity.

Source.Version is a contract compatibility boundary. Source.Revision and Definition.Revision identify current implementations. Resolve freezes the opened definition and source descriptor; Version classifies the host's latest definition and source as current, update-available or incompatible (CompareVersion is the same rule for hosts that already hold both revisions), and Changed reports any non-current status. Reopening resolves the latest compatible source. An incompatible source contract or a view the source no longer offers returns FailedPrecondition (cause ErrIncompatible) from Resolve; no silent fallback. Compose degrades only that placement: its grid group keeps its identity, caption and width, carries `unavailable: "report-incompatible"` on the wire, never executes the source, and its Resolved entry has Status VersionIncompatible. The other placements compose and execute normally.

On the client, LensDashboard's reportPlacementHost reports each placement's status by placement ID (the report group ID on the wire). Update-available keeps the opened figures and offers Update (host.update, then a document refresh) or Keep (host.keep). Incompatible, from the host or from the wire group, replaces the placement's figures with an explanation on screen and in print. compareReportVersion mirrors CompareVersion. reportPlacementActions returns the drill/save/export operations a placement may offer: the source must declare the operation and the effective context must not conflict, carry unsupported filters, or list the operation in unsupportedOperations.

A Host.Report that returns ErrReportDeleted or ErrReportForbidden (bare or wrapped) degrades only that placement to `unavailable: "report-deleted"` or `"report-forbidden"`; Resolved.Unavailable carries the reason. A forbidden slot keeps only its width: no caption, title or filter context reaches the wire. Any other Host.Report error still fails the composition.

The client renders each placement as one card. ReportPlacementHost members are optional: status/update/keep (versions), unavailable (a reason learned after opening), capabilities (source drill/save/export) and actions (open, edit, configure, copy, remove). reportPlacementMenu shows an item only when its handler exists; edit and copy also need save under the card's effective context; deleted and forbidden placements offer only removal. The card footer states the oldest member calculation time in the card's calendar timezone, reports a failed member instead of claiming freshness, and its Retry re-requests only that card's failed members. A panel that names a host renderer (panel.Renderer) is drawn by LensDashboard's `renderers[name]` inside the SDK frame; without one the card shows a compatibility state, never the panel kind.

The Solid createReportDraft API separates edits from acknowledged storage. Cancel restores the saved base; save/publish is an explicit host call carrying expectedRevision. Failure keeps edits; edits made during an earlier save are retained. Storage, ownership, publishing and conflict policy are host responsibilities.

Adding reports is explicit. A host implements Library (Search over CatalogQuery: search text, owner scope all/personal/shared, where shared lists only reports other people shared and built-in reports appear under all, opaque cursor, page size, target composition) and returns CatalogPage entries it has already authorized: ownership, owner, source label, description, a compound report's member count as one choice, a restriction note, and Placed in the target (MarkPlaced/PlacementCounts). A page has no total, so hidden reports leave no count. Catalog.Search serves code-authored definitions as system reports. On the client, ReportPicker takes a ReportCatalogHost (search, optional preview returning a DashboardDocument, optional generate) and the target. It opens as a drawer from the inline end, so the dashboard stays in view; the reader selects by clicking anywhere on a row (the checkbox stays its keyboard control), previews without losing search or selection, and confirms "Add N". When the host provides generate, a "Create with AI" section takes a plain-language description (ReportCardGenerateRequest: prompt and target), shows the host's stages (starting, schema, generating, validating), can be stopped, and on success lists the new personal report first and selects it; the host stores it, so the personal report may already be saved when the reader presses Stop, Cancel or closes the drawer; those do not discard it. The dashboard draft stays unchanged until the reader confirms with Add. Until then the dashboard draft does not change; the picker hands an ordered ReportPickerConfirmation whose id stays stable across retries of the same choice, and closes only after the caller resolves. appendReportPicks appends library placements (inheriting filters) to the end of a draft composition and is idempotent per confirmation; a placed report needs the explicit "Add another card" choice. ReportDestinationPicker (Destinations interface) adds an opened report to an existing or new dashboard and passes the shown EffectiveContext to the host, which places it with placeOpenedReport. Runtime strings of both dialogs are in document.RuntimeI18nKeys; LensMessagesProvider supplies them outside a document.

Saving an exploration is a report, not a placement. An explorer node declares the report dimension its selection constrains (explore.Node.WithDimension); the wire Level carries it as `dimension` and every child Node its raw `value`. A drill position inside a report placement is then a slice of that report's source: the placement's EffectiveContext (period and restrictions, each with its origin) plus one constraint per drill step. LensDashboard's `investigation` (InvestigationHost) offers "Save investigation" on the card of the current level only when the source declares save under that context (reportPlacementActions) and every drill dimension is one the source accepts for saving (input.operationDimensions.save, else the source dimensions); otherwise the card states why (not a report, source cannot save, blocked context, undeclared level, unsupported dimension, a selection contradicting an applied filter) and offers no builder. The form holds the suggested name, source, period and constraints with their origins and says the report is recalculated when opened. "Save draft", "Publish" and "Publish and add…" call host.save with an InvestigationProposal (source, view, ContextFilters, origin; never a snapshot) and an id that stays stable across retries of the same proposal and intent, so a retry never creates a second report. "Publish and add…" then opens ReportDestinationPicker over host.destinations and calls host.place; if publishing succeeded and adding failed, the form keeps the created report's link and retries only adding. The explored dashboard is not modified. A panel declaring `ratio` (panel.Builder.Ratio: numerator and denominator fields with labels and a description) shows its host-computed parts on the card and never sums rows into a total or shares.

Leaving Lens for a host page carries the exploration back. With LensDashboard `returnContext`, links of navigate-to-leaf actions get `lens-return`: a versioned token (pkg/lens/drillreturn, mirrored by readReturnContext/backURL in @iota-uz/sdk/lens; fixtures/return-context.json is the shared fixture) holding the site-relative Lens URL (levels, perspective and filters, so it works in a new tab), the dashboard title and the level labels. The host renders Back with Context.BackURL(leaf, state); its own opaque state (sort, page, scroll) travels in `lens-host` and is handed back as Context.Host the next time the same leaf is opened from that exploration. When a drill or page query finds its snapshot gone, the level shows why instead of the parent's figures and the board offers Recalculate; afterwards it states the time of the new calculation, so an old headline and recalculated rows are never mixed silently.

ReportCompositionEditor edits a createReportDraft composition as one session. "Add report" opens the picker and appends the confirmed cards, focusing the first and stating how many were added. Cards move by dragging their handle or with the arrow keys on it, resize with the width slider (drag or arrow/Home/End keys) and wrap when a row exceeds twelve columns; on a narrow screen they stack in reading order. Configure card changes only the placement's caption, width and local period; Edit report first states how many places use the shared report (host usage) and offers an independent copy. Nothing is saved until the reader chooses Save draft/Publish (new) or Save changes (existing); success is shown after the host acknowledges, a failure keeps every edit, and Cancel restores the saved base. A host save that throws ReportRevisionConflictError(latest) never overwrites silently: the reader keeps their changes (draft.rebase(latest, 'keep'), saved against the new revision), loads the other version (rebase discard) or saves a separate copy through the host. createReportLeaveGuard adds the browser unload warning while dirty and gives hosts request() for in-app navigation; a failed save never allows leaving. A Proposal (Go report.Proposal, generated) carries a base token from reportDraftToken; any local change after that token makes it stale, so it cannot be applied, only prepared again or opened as a separate draft by the host. Apply replaces the draft composition as a whole without publishing; Reject leaves the draft unchanged. Proposals never edit a shared definition. The proposal panel lists Add / Change / Remove by card title and previews the proposed layout on the twelve-column grid before Apply. While the host is still preparing one, it passes proposalRequest ({id, base: reportDraftToken(draft)}); the editor shows it as being prepared, and a manual edit before it arrives marks it stale at once (proposalHandlers.restart prepares it again), so the arriving proposal cannot be applied. Pass placements(reportId) instead of usage to list where a shared report is placed, the reader's card first, before Edit report.

ReportDefinitionEditor edits a shared report definition (createReportDraft over a Definition) and is titled "Edit report: …", unlike Configure card. It opens with the reach of a save (host placements) and an independent copy (onCopy). When entered from a dashboard, context ({origin, filters}) shows where the filters come from; they drive only the preview (the reader can switch to the report defaults) and are never written into the definition, while onSaveSlice lets the host save that view (the report with the dashboard's filters, offered while the preview shows them) as a new report. Parameter controls are the host's (renderParameters); a change shows in the host's renderPreview at once, marked Not saved, and persists only through Save changes. Save failure keeps the edits, a ReportRevisionConflictError offers Load their version / Keep my changes / Save as a separate copy, Cancel restores the whole session, and the leave guard asks Save / Leave without saving / Stay; a rename counts as unsaved while it is typed. Both editors take locale to use the runtime's built-in ru and uz text outside a document.

Hosts restore stored records with DecodeDefinition and DecodeComposition (TypeScript: parseReportDefinition and parseReportComposition). Both reject unknown fields such as an execution snapshot ID instead of dropping them. web/lens/fixtures/report-contract.json is the shared acceptance fixture: Go (acceptance_test.go) and TypeScript (src/reports/contract.test.ts) store it in two independent host adapters, restore identical records, and classify the same version cases.

Independent report copies get a new ID. Placement duplicates keep their report reference. A saved relative period remains a relative value in the source's parameter schema; sources resolve it at execution time.

Public boundaries: github.com/iota-uz/iota-sdk/pkg/lens/report and @iota-uz/sdk/lens. Go owns generated TypeScript/Zod definitions under src/reports/contract. No new npm distribution.
