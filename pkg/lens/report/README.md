# Reusable Lens reports

A Definition stores a permanent source reference, source contract version, view and parameters. It never stores SQL, an executed frame or a snapshot ID. A Placement references that definition and owns its caption, width and parameter overrides. A Composition stores ordered rows of placements.

The host resolves authorized definitions and sources. Catalog is the code-authored adapter; persistence implements the same Host interface. SourceFunc binds domain data to existing Lens DashboardSpec blocks. Compose namespaces each block's datasets, panels, variables and explorers and lowers it into the existing runtime. It does not add a request manager or executor. Grid groups preserve compound blocks, their titles and nested row geometry on the wire.

Parameters are applied in definition → composition → placement order. Unsupported parameters and views fail explicitly. Sources validate parameter values and bind them before building a spec. Calendar/timezone, dimension semantics, SQL and tenant/user scope remain host-owned. Composition.Context supplies immutable host calendar and dashboard/card/section/group layers. Definition.Filters owns saved report defaults. Periods override by scope; dimension constraints intersect with full provenance. Unsupported or conflicting contexts block source execution. ContextSource must translate the resolved context explicitly; no fallback executes a broader query. The wire group carries the same effective context and identity.

Source.Version is a contract compatibility boundary. Source.Revision and Definition.Revision identify current implementations. Resolve freezes the opened definition and source descriptor; Version classifies the host's latest definition and source as current, update-available or incompatible (CompareVersion is the same rule for hosts that already hold both revisions), and Changed reports any non-current status. Reopening resolves the latest compatible source. An incompatible source contract or a view the source no longer offers returns FailedPrecondition (cause ErrIncompatible) from Resolve; no silent fallback. Compose degrades only that placement: its grid group keeps its identity, caption and width, carries `unavailable: "report-incompatible"` on the wire, never executes the source, and its Resolved entry has Status VersionIncompatible. The other placements compose and execute normally.

On the client, LensDashboard's reportPlacementHost reports each placement's status by placement ID (the report group ID on the wire). Update-available keeps the opened figures and offers Update (host.update, then a document refresh) or Keep (host.keep). Incompatible, from the host or from the wire group, replaces the placement's figures with an explanation on screen and in print. compareReportVersion mirrors CompareVersion. reportPlacementActions returns the drill/save/export operations a placement may offer: the source must declare the operation and the effective context must not conflict, carry unsupported filters, or list the operation in unsupportedOperations.

A Host.Report that returns ErrReportDeleted or ErrReportForbidden (bare or wrapped) degrades only that placement to `unavailable: "report-deleted"` or `"report-forbidden"`; Resolved.Unavailable carries the reason. A forbidden slot keeps only its width: no caption, title or filter context reaches the wire. Any other Host.Report error still fails the composition.

The client renders each placement as one card. ReportPlacementHost members are optional: status/update/keep (versions), unavailable (a reason learned after opening), capabilities (source drill/save/export) and actions (open, edit, configure, copy, remove). reportPlacementMenu shows an item only when its handler exists; edit and copy also need save under the card's effective context; deleted and forbidden placements offer only removal. The card footer states the oldest member calculation time in the card's calendar timezone, reports a failed member instead of claiming freshness, and its Retry re-requests only that card's failed members. A panel that names a host renderer (panel.Renderer) is drawn by LensDashboard's `renderers[name]` inside the SDK frame; without one the card shows a compatibility state, never the panel kind.

The Solid createReportDraft API separates edits from acknowledged storage. Cancel restores the saved base; save/publish is an explicit host call carrying expectedRevision. Failure keeps edits; edits made during an earlier save are retained. Storage, ownership, publishing and conflict policy are host responsibilities.

Adding reports is explicit. A host implements Library (Search over CatalogQuery: search text, owner scope all/personal/shared, opaque cursor, page size, target composition) and returns CatalogPage entries it has already authorized: ownership, owner, source label, description, a compound report's member count as one choice, a restriction note, and Placed in the target (MarkPlaced/PlacementCounts). A page has no total, so hidden reports leave no count. Catalog.Search serves code-authored definitions as system reports. On the client, ReportPicker takes a ReportCatalogHost (search, optional preview returning a DashboardDocument) and the target; the reader selects with checkboxes, previews without losing search or selection, and confirms "Add N". Until then nothing changes; the picker hands an ordered ReportPickerConfirmation whose id stays stable across retries of the same choice, and closes only after the caller resolves. appendReportPicks appends library placements (inheriting filters) to the end of a draft composition and is idempotent per confirmation; a placed report needs the explicit "Add another card" choice. ReportDestinationPicker (Destinations interface) adds an opened report to an existing or new dashboard and passes the shown EffectiveContext to the host, which places it with placeOpenedReport. Runtime strings of both dialogs are in document.RuntimeI18nKeys; LensMessagesProvider supplies them outside a document.

Independent report copies get a new ID. Placement duplicates keep their report reference. A saved relative period remains a relative value in the source's parameter schema; sources resolve it at execution time.

Public boundaries: github.com/iota-uz/iota-sdk/pkg/lens/report and @iota-uz/sdk/lens. Go owns generated TypeScript/Zod definitions under src/reports/contract. No new npm distribution.
