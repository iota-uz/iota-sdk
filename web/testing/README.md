# Browser testing contracts

Consumers import `@iota-uz/sdk/testing` from the same immutable SDK candidate as their application. Install the optional `@playwright/test` peer in the test project. This entry point runs in the Playwright Node process, never in an application bundle.

`actionAndResponse(page, match, action)` registers before the action. Match is `{ method, pathname }` or a consumer response predicate. An absent response rejects. `actionAndHtmxResponse` additionally follows the matching production HTMX XHR through `afterSettle`, including replaced targets; server refusals reject. Superseded XHR aborts terminate their records, while a newer send failure rejects and a winning response must settle. `actionAndHtmxSettled` scopes the same event tracking to a target selector. These helpers require the production HTMX lifecycle, not synthetic host events.

`actionAndValidationRefusal(page, form, action)` observes native invalid events and checks that the form did not submit or issue its configured submission request during the interaction. It returns control name and browser validation message without spending a network timeout. Keep integration tests for server-side validation.

`expectComponentReady(page, root, { readinessAttribute })` requires a declared readiness marker, visible root and loaded fonts. The default marker is `data-component-ready="true"`; existing hosts can select their own marker. Hosts must set readiness only after their chart/backend requirements complete. `ComponentHost` discovers typed `ComponentCase` metadata and navigates to real components with actual assets. `openComponentCase` applies viewport and waits for host readiness. Locale/theme/state application remains the host adapter's responsibility; metadata is not an alternative rendering language. Existing Lens baselines and screenshot runner remain canonical.

`createEnvironmentTest(test, { lifecycle, scenarios, identity })` accepts the consumer’s Playwright base test and creates worker environment and lazy worker identity fixtures plus test-scoped scenario leases. Readiness failures stop the environment; each scope is disposed even after partially failed preparation. A retry receives a fresh physical scope. The lifecycle adapter maps the Go testenv descriptor and owns its process/DB allocation. Identity adapters write storage state beneath that environment's artifact directory and must avoid sharing mutable server account state across workers. Login/session tests continue using the actual form.

`withEnvironment`, `withScenario`, and `lazyIdentities` are also available for adapters that already own their Playwright fixture graph. Teardown errors fail the test. Browser helper tests are characterisation of new contracts; they use the production HTMX asset and carry false-green notes.

Run `pnpm --dir web/testing test`, `pnpm build`, and `pnpm check:sdk`. Client-host product editor and Solid UI/Templ parity consume the published testing subpath. Their screenshots remain assertions only where an approved baseline is used; failure screenshots alone are diagnostics.

The shell-free `createProcessEnvironmentDriver` adapter starts one persistent `cmd/testenv` process, sends correlated newline JSON start/stop commands and maps its descriptor to the fixtures. Configure the executable, args, environment and per-worker spec in the consumer. Always `close()` the driver after worker fixtures stop: EOF asks the Go driver to clean all remaining resources. Driver stdout belongs exclusively to protocol responses; stderr contains diagnostics. Protocol errors, unexpected exit and request timeout fail tests.

`createHttpScenarioControl(environment, token)` is the adapter for the credential-protected Go registry. It reserves an owned scope before preparing, verifies the environment response header and disposes the scope. Supply `name`, `version`, logical `seed`, explicit RFC3339 `now`, and typed domain `params`; the physical scope remains separate from the logical seed. `ScenarioControlError.code` and `.status` expose typed refusals. Requests are bounded and do not follow redirects carrying the control credential.
