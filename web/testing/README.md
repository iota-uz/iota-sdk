# Browser testing contracts

Consumers import `@iota-uz/sdk/testing` from the same immutable SDK candidate as their application. Install the optional `@playwright/test` peer in the test project. This entry point runs in the Playwright Node process, never in an application bundle.

`actionAndResponse(page, match, action)` registers before the action, so a response that arrives before the click resolves is still captured. Match is `{ method, pathname }` or a consumer response predicate. An absent response rejects with the expected method/path; there is no success path after the timeout, so never wrap a required request in a `catch` that continues. `actionAndHtmxResponse` additionally follows the matching production HTMX XHR until it settles (or loads without swapped content, or navigates via HX-Redirect/HX-Refresh/HX-Location), including replaced targets; server refusals reject. Superseded XHR aborts terminate their records, while a newer send failure rejects and a winning response must settle.

`actionAndHtmxSettled(page, target, action, { ready })` waits for every HTMX request whose target is, contains or is inside the CSS selector `target`; scope membership is re-evaluated at `beforeSwap`, so `HX-Retarget` and `beforeSwap` overrides are followed. Each request must swap and settle; a request whose swap produced no content (`hx-swap="none"`, an empty `outerHTML` replacement) completes when it loads, while a delayed `swap:` still waits for the swap. Listeners are attached to the requesting element, the target and every swapped-in element, so detached rows, replaced targets and content detached by a later swap still report. Refusals, send errors, load errors and HTMX timeouts reject promptly with status, method and URL; a response that navigates (`HX-Redirect`, `HX-Refresh`, `HX-Location`) rejects with a navigation diagnostic, so wait for the URL instead; an action that issues no request for the target rejects with `Action issued no HTMX request targeted …`. Every request observed during the wait must answer before completion, since `HX-Retarget` can still move it into the scope; an unrelated slow request (a long poll started during the wait) therefore delays completion until it answers or the budget ends. Requests started while earlier ones are pending are included; requests triggered later (`delay`, `intersect`, header-triggered listeners) need their own call. Afterwards at least one element must match `target`, no match may carry transient swap classes, and `ready(locator, { timeoutMs })` runs with the remaining budget. The budget (`timeoutMs`, default 10000) starts once `action` resolves; the action keeps its own Playwright timeouts. A selector that is not CSS rejects before the action runs. These helpers require the production HTMX lifecycle, not synthetic host events.

`actionAndValidationRefusal(page, form, action)` observes native invalid events and checks that the form did not submit, did not start an HTMX request and did not issue a network request to any submission URL the form or its submit buttons declare (`hx-post/put/patch/delete/get`, `formaction`/`formmethod`, or the form `action`/`method`) during the interaction. Its budget starts once `action` resolves. It waits for the invalid event, verifies the reported control still matches `:invalid`, and returns control name and browser validation message without spending a network timeout. Keep integration tests for server-side validation.

`expectComponentReady(page, root, { readinessAttribute, charts })` requires exactly one visible root with the declared readiness marker (default `data-component-ready="true"`), loaded fonts and, when given, every chart in `charts` carrying `data-chart-ready="true"`. Each poll takes one atomic page-side snapshot, so a root that detaches or remounts cannot stall the wait past its budget. A timeout rejects with `ReadinessError`, whose `.state` keeps the marker value, root count, visibility, font status, chart markers and an HTML excerpt. Hosts set readiness only after their chart/backend requirements complete; network idleness and fixed delays are not readiness.

`ComponentHost` is the adapter over an existing fixture host: `cases()` discovers typed `ComponentCase` metadata, `navigate(page, case)` renders the real exported component with production assets, applies locale/theme and enters the declared state through real interactions, and `readiness` selects the host marker. `openComponentCase` applies the case viewport, navigates and waits for readiness; `componentCase(host, id)` looks a case up by ID. `assertCaseCoverage(cases, { states, locales, themes, viewports })` proves each declared value appears in some case without enumerating the Cartesian product. Metadata is not an alternative rendering language, and mocks belong only at the host's declared backend boundary; drive loading/stale states through controlled gates rather than delays. The pilots are `web/client-host/browser-tests/product-editor.host.ts` (editing/loading/empty/error/stale over a gated save backend, en/ru, light/dark, desktop/narrow) and `web/solid-ui/vr/gallery.host.ts` (catalog specimens, discovered from the gallery catalog). Existing Lens baselines and screenshot runner remain canonical.

`expectNoA11yViolations(page, { include, exclude, disableRules })` runs axe on the page (or the `include` selectors minus `exclude`) and rejects with `A11yViolationError` when any violation has impact `serious` or `critical`; `.violations` keeps those. The full axe report is attached to the running test as `a11y-report.json` whether the check passes or not (pass `testInfo` explicitly outside a Playwright test). `disableRules` is for a rule the test explains in a comment. The engine is the optional peer `@axe-core/playwright`: install it in the test project. Without it the subpath still imports, and the helper rejects with `A11yDependencyError` naming the package to install.

`attachDiagnosticScreenshot(page | locator, testInfo, name)` attaches a `diagnostic-*` screenshot that is never compared. Approved baselines are asserted only with `expect(...).toHaveScreenshot` in a host's VR runner. Component fixtures do not replace route, RBAC or locale integration checks, and a defect seen in the application browser stays a browser test against the application.

`createEnvironmentTest(test, { lifecycle, scenarios, identity })` accepts the consumer’s Playwright base test and creates worker environment and lazy worker identity fixtures plus test-scoped scenario leases. Readiness failures stop the environment; each scope is disposed even after partially failed preparation. A retry receives a fresh physical scope. The lifecycle adapter maps the Go testenv descriptor and owns its process/DB allocation. Identity adapters keep storage state in memory or private run-owned files excluded from uploaded diagnostics, and must avoid sharing mutable server account state across workers. Login/session tests continue using the actual form.

`withEnvironment`, `withScenario`, and `lazyIdentities` are also available for adapters that already own their Playwright fixture graph. Teardown errors fail the test. Browser helper tests are characterisation of new contracts; they use the production HTMX asset and carry false-green notes.

Run `pnpm --dir web/testing test`, `pnpm build`, and `pnpm check:sdk`. Client-host product editor and Solid UI/Templ parity consume the published testing subpath. Their screenshots remain assertions only where an approved baseline is used; failure screenshots alone are diagnostics.

The shell-free `createProcessEnvironmentDriver` adapter starts one persistent `cmd/testenv` process, sends correlated newline JSON start/stop commands and maps its descriptor to the fixtures. Configure the executable, args, environment and per-worker spec in the consumer. Always `close()` the driver after worker fixtures stop: EOF asks the Go driver to clean all remaining resources. Driver stdout belongs exclusively to protocol responses; stderr contains diagnostics. Protocol errors, unexpected exit and request timeout fail tests.

`createHttpScenarioControl(environment, token)` is the adapter for the credential-protected Go registry. It reserves an owned scope before preparing, verifies the environment response header and disposes the scope. Supply `name`, `version`, logical `seed`, explicit RFC3339 `now`, and typed domain `params`; the physical scope remains separate from the logical seed. `ScenarioControlError.code` and `.status` expose typed refusals. Requests are bounded and do not follow redirects carrying the control credential.

For an opt-in isolated attempt or a worker environment, use `createEnvironmentLeaseTest(test, { scope: 'test' | 'worker', runName, name, lifecycle })`. Its `environmentLease` fixture supplies `baseURL`. The lifecycle factory receives worker/parallel indices, test ID and retry for test scope, plus the run and environment names. Names default to a fresh run UUID and a worker/attempt suffix; consumers may provide a stable run name and a naming callback. Preserve attempt uniqueness when overriding names. The consumer's base test is injected; no second Playwright runtime is loaded.

`acquireEnvironmentLease(lifecycle, workerIndex, { closeDriver })` supports consumers that acquire several environments. Its idempotent `close()` stops the environment, then closes the driver even if stopping fails. Readiness failure compensates both resources; startup failure closes the driver. `withEnvironmentLease` additionally preserves an assertion failure alongside cleanup failures, as `withScenario` and `withEnvironment` do. A fixture lifecycle may expose `close()` to use the same compensation automatically.

Process-driver shutdown is bounded: EOF receives 35 seconds by default (allowing the Go driver's 30-second cleanup), then the owned subprocess receives SIGINT and has 10 seconds before SIGKILL. Configure `closeTimeoutMs` and `killTimeoutMs` for other adapters. A forced shutdown fails with `DriverError.code = 'close_timeout'`; it cannot guarantee cleanup of arbitrary child processes/resources, so adapters must implement compensation and retain artifact directories for diagnosis. `DriverError` preserves `operation`, known environment/artifact fields, partial descriptors and recursive cleanup `causes`. Request timeout does not establish that resource cleanup succeeded.

`createHttpTestControls(environment, token)` covers the scoped controls of the same Go registry (`pkg/testenv`): `jobs.run/status/wait` run consumer-registered handlers and wait for named conditions. `wait` takes `timeoutMs` 1..120000 and rejects with `JobWaitError`, whose `result` holds execution state and checks. `providers.script/calls/waitHeld/release/forget` drive scripted fakes with hold/release gates. `clock.now/advance` control dedicated server time; pass `clock.now()` to `page.clock` so browser and scenario time agree. `manifest/replay` reproduce a scope in a fresh environment. Every call names the physical scope, and shared environments refuse clock control.
