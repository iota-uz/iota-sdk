## Решение

Пользователь выбрал явный локальный `sdkctl promote` вместо GitHub Apps,
cron и фоновой модификации PR потребителей. Команда использует существующий gh
login, требует merge SDK PR, находит готовый релиз либо ждёт/запускает release.yml.
После успешной публикации изменяет только локальные зависимости. Агент проверяет,
коммитит и пушит обычным способом. Повторная команда продолжает удалённый релиз.

В SDK сохраняется состояние кандидата и история готовых версий. Полный CI
выполняется до публикации неизменяемого кандидата. Git tag создаёт GITHUB_TOKEN,
npm использует OIDC. Готовность фиксируется после проверки обеих публикаций;
GitHub Release не является частью протокола. Для повторной публикации сохраняется
оригинальный Actions artifact на 90 дней; отсутствие архива останавливает recovery.

## Обоснование и последствия

Одна команда доводит потребителя от preview до production pin без установки
ботов и секретов. Новая публикация требует у локального gh пользователя права
запуска SDK Actions. Закрытый терминал не останавливает CI, но локальное обновление
потребителя требует повторного promote. Consumer CI проверяет production identity
обычным read-only job. Политика SemVer и дешёвые PR checks сохраняются.

## Проверка

Go tests покрывают повторный запуск, подхват активного workflow и откат локальных
файлов. Node tests проверяют частичную публикацию и запрет конфликтующих версий.
Настройка npm OIDC и реальная публикация проверяются при rollout отдельно.
