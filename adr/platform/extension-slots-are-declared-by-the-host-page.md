## Решение

Слот объявляет страница, которая его показывает: стабильный ID, типизированные
`props` и необязательное право. Нативные страницы объявляют слот обычным нативным
ресурсом (`manifest.Resource{Kind: slot}`), пакеты — `defineSlot` в графе
контрактов, поэтому другие пакеты достают его через kit с типом `props`.

Вклады (`slot(ref, Component, {order, permission})`) аддитивны: строки в
`bindings` нет, вклад действует, пока активна версия пакета. Для каждого слота
индекс снимка хранит вклады в порядке (order, пакет, ID); сервер отдаёт зрителю
только те, чьё право у него есть, и ничего, если право слота ему недоступно.
Запрещённый вклад не попадает ни в HTML, ни в данные страницы. `props` страницы
проверяются по объявленному типу до отправки в браузер.

Страницы Templ получают `shellext.Slot(ctx, id, props)`: элемент-точка монтирования
с props, ссылками на модули и окружением (достаточно для HTMX-фрагмента) плюс
однократный на запрос вход в runtime host. Страницы Solid и оболочка получают те же
вклады в `PageData.slots` / `RuntimeContext.slots` и рисуют `<Slot slot props/>`.
Браузерный host монтирует каждый вклад в отдельный Solid-корень и освобождает его
при уходе элемента из документа; поздно пришедший модуль отбрасывается.

Рендерер ячейки (`cell(column, Component)`) — остров поверх стандартной ячейки:
HTML сервера осмыслен без JavaScript, фильтры, сортировка и экспорт читают сырое
значение. Замена экрана требует права нативного маршрута и собственного права
страницы; кандидат на замену не обслуживается без привязки `screen`.

## Последствия

Страница, показывающая необъявленный слот, ничего не рисует и пишет предупреждение.
Пока регистрация нативных ресурсов не унифицирована, приложение передаёт
объявления CRM (`modules/crm/extension`) в `runtime.Config.NativeResources`.
Проп компонента `<Slot>` называется `slot`: `ref` Solid-компилятор резервирует.
